# Работа 1. Родственные отношения

**Цель:** освоить факты, правила, переменные и поиск по базе знаний.

**Задание:** создать базу родственников и семантическую сеть; реализовать №21 «сводный брат», №29 «мужской пол», №37 «деверь», №45 «ятровь». По методичке нужно минимум семь запросов; ниже приведено десять.

## Исходные данные

Виктор и Галина — родители Сергея и Андрея. Сергей и Елена — родители Димы и Кати. Андрей и Марина — родители Ивана. Олег и Нина — родители Никиты. Сейчас Сергей женат на Ольге, Елена замужем за Олегом, Дима женат на Анне. Браки Виктора с Галиной и Андрея с Мариной также текущие.

Бывшие браки не хранятся как текущие. Наличие общих детей не используется как доказательство текущего брака. Стрелки на схеме соответствуют всем фактам `father/2` и `mother/2`.

**Сводный брат** здесь — сын отчима или мачехи, с которым нет общих биологических родителей. Брат по одному общему родителю называется неполнородным. Методичка не уточняет термин «сводный», поэтому выбранное толкование нужно назвать при защите.

## Предикаты

| Предикат | Смысл аргументов |
|---|---|
| `male(X)`, `female(X)` | пол человека |
| `father(P,C)`, `mother(P,C)` | родитель, ребёнок |
| `married(H,W)` | текущие муж и жена |
| `parent(P,C)` | родитель любого пола |
| `spouse(X,Y)` | супруги в любом порядке |
| `brother(B,P)` | брат B человека P, по общему отцу или матери |
| `stepbrother(B,P)` | сводный брат B человека P |
| `dever(B,W)` | B — брат мужа женщины W |
| `yatrov(Y,W)` | Y — жена брата мужа женщины W |
| `demo` | демонстрационный вывод |

## Запросы и результаты

В таблице указаны различные ответы; порядок может отличаться при изменении порядка фактов. После упрощения `brother/2` запросы `dever/2` и `yatrov/2` могут возвращать одинаковый ответ дважды — по общему отцу и по общей матери. В демонстрации повторы удаляются.

| № | Запрос | Ответ |
|---|---|---|
| 1 | `stepbrother(X, 'Дима').` | `X = 'Никита'` |
| 2 | `stepbrother('Никита', X).` | `X = 'Дима' ; X = 'Катя'` |
| 3 | `stepbrother('Дима', 'Никита').` | `true` |
| 4 | `stepbrother('Иван', 'Дима').` | `false` |
| 5 | `male('Дима').` | `true` |
| 6 | `male('Катя').` | `false` |
| 7 | `male(X).` | `'Виктор', 'Сергей', 'Андрей', 'Олег', 'Дима', 'Иван', 'Никита'` |
| 8 | `dever(X, 'Ольга').` | `X = 'Андрей'` |
| 9 | `dever(X, 'Марина').` | `X = 'Сергей'` |
| 10 | `yatrov(X, 'Ольга').` | `X = 'Марина'` |
| 11 | `yatrov(X, 'Марина').` | `X = 'Ольга'` |
| 12 | `dever(X, 'Анна').` | `false`: в базе нет брата Димы |

Списки без повторений удобно получать так: `setof(X, male(X), Men).` Если решений нет, `setof/3` завершается неуспехом; `findall/3` возвращает `[]`.

## Как находятся ответы

**Никита — сводный брат Димы.** Запрос `stepbrother(B,'Дима')` сначала выбирает мужчину `B`. Затем `parent(P1,'Дима')` находит родителя. Успешный путь: `P1='Елена'`; `spouse('Елена',P2)` даёт `P2='Олег'`; `parent('Олег',B)` даёт `B='Никита'`. Дима и Никита различны; поиск общего родителя неуспешен, поэтому отрицание проходит. Ответ `B='Никита'`.

**Андрей — деверь Ольги.** `married(Husband,'Ольга')` связывает `Husband='Сергей'`. Затем `brother(B,'Сергей')` находит Андрея: он мужчина, у него с Сергеем общий отец Виктор, и это разные люди. Правило использует `parent/2`: общий родитель может быть отцом или матерью. При двух общих родителях один брат находится дважды. В `demo/0` повторы удаляются через `sort/2`; для самостоятельных запросов можно использовать `setof/3`.

**Марина — ятровь Ольги.** К предыдущей цепочке добавляется `married('Андрей',Woman)`, откуда `Woman='Марина'`.

**Дима — мужчина.** `male('Дима')` непосредственно совпадает с фактом; вычислять пол по наличию детей не требуется.

## Что объяснить при защите

`father('Сергей','Дима').` — факт. `parent(Parent,Child) :- father(Parent,Child).` — правило: Parent является родителем Child, если Parent является отцом Child. `:-` читается «если», запятая означает «и», точка завершает предложение. Несколько правил одного предиката задают альтернативы.

`'Дима'` — атом в одинарных кавычках, `Person` — переменная на английском. Кавычки нужны, чтобы имя с заглавной русской буквы не считалось переменной. Унификация сопоставляет запрос с фактами и правилами и связывает переменные. Цели проверяются слева направо, альтернативы перебираются сверху вниз; при неудаче происходит возврат к предыдущему выбору.

`dif(X,Y)` требует различия людей. `\+ Goal` означает, что цель `Goal` не удалось доказать по текущей базе; это отрицание как неуспех. В проверке общего родителя люди уже выбраны. Недостающие факты о родителях могли бы изменить результат, поэтому база считается полной для перечисленных семей.

`stepbrother/2` может иметь несколько путей доказательства в более сложной базе (например, если оба родителя вступили в новые браки с обоими родителями другого ребёнка). Для выдачи множества родственников используй `setof/3`.

**Вывод:** факты задают исходные связи, а правила выводят новые отношения через общие переменные и перебор. Семантическая сеть помогает проследить доказательство запроса.
