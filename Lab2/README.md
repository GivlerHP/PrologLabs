
## Часть 1, вариант 6: табель оценок

### Точное задание из методички

**Часть 1. Создание структурированной базы знаний**

> Необходимо создать хорошо структурированную базу знаний и систему запросов к ней в соответствии с вариантами задания. При разработке базы знаний для хранения информации можно создать только один предикат.

**Вариант 6:**

> Разработать базу знаний «табель оценок» (tabel) на основе успеваемости группы студентов.

Источник: П. В. Новиков, «Логическое программирование на Visual Prolog 5.2», печатная страница 22 (страница 20 PDF).

### Реализация

Файл: `part1_tabel.pl`. Три студента одной группы, три предмета. Используется пятибалльная шкала (1–5), положительная оценка от 3. Шкала выбрана для примера: в задании она не указана. Единственный предикат хранения — `tabel/4`; остальные — правила поиска, отдельно данные не хранят.

```prolog
tabel(fio('Иванов', 'Дима', 'Сергеевич'), 'ПИ-21', 'Prolog',
      mark(5, date(20, 1, 2027))).
```

Это факт: Дима Иванов из группы ПИ-21 получил 5 по Prolog 20 января 2027 года. Четыре аргумента `tabel`: ФИО, группа, предмет, результат. `fio` объединяет фамилию, имя и отчество; `mark` — оценку и дату; внутри `mark` вложена структура `date`.

### Запросы для демонстрации

**Удобные запросы с фамилиями и полным ФИО:**

```prolog
% Все студенты — каждый один раз.
student(Surname, Name, Patronymic).
```

Ответы: Иванов Дима Сергеевич; Петров Максим Олегович; Смирнова Алина Андреевна.

```prolog
% Только фамилии — без повторов по предметам.
student(Surname, _, _).
```

Ответы: Иванов, Петров, Смирнова. Если в базе появятся однофамильцы, одна фамилия может встретиться у разных студентов.

```prolog
% Полное ФИО и оценка каждого за Prolog.
student_grade(Surname, Name, Patronymic, 'Prolog', Grade).
```

Ответы: Иванов Дима Сергеевич — 5; Петров Максим Олегович — 2; Смирнова Алина Андреевна — 5.

```prolog
% Все оценки студента с заданными фамилией и именем.
student_grade('Иванов', 'Дима', Patronymic, Subject, Grade).
```

Ответы: Сергеевич, Логика — 5; Сергеевич, Prolog — 5; Сергеевич, Математика — 4.

```prolog
% Все оценки с полным ФИО.
student_grade(Surname, Name, Patronymic, Subject, Grade).
```

Девять ответов. Этот удобный запрос не включает группу и дату; для просмотра всех полей используй `tabel/4` ниже.

**1. Вся база со всеми полями — обязательный запрос по методичке:**

```prolog
tabel(Student, Group, Subject, Result).
```

Нажми All: будет девять ответов с полным ФИО, группой, предметом, оценкой и датой.

**2. Все оценки Димы:**

```prolog
student_mark('Дима', Subject, Grade).
```

Логика — 5; Prolog — 5; Математика — 4.

**3. Все оценки за Prolog:**

```prolog
student_mark(Name, 'Prolog', Grade).
```

Дима — 5; Максим — 2; Алина — 5.

**4. Неудовлетворительные оценки:**

```prolog
failed_student(Name, Subject, Grade).
```

Максим — Prolog — 2.

**5. Отличные оценки:**

```prolog
high_mark(Name, Subject, Grade).
```

Дима — Логика — 5; Дима — Prolog — 5; Алина — Логика — 5; Алина — Prolog — 5; Алина — Математика — 5.

**6. Оценки за 20 января:**

```prolog
tabel(fio(_, Name, _), _, Subject, mark(Grade, date(20, 1, 2027))).
```

Дима — Prolog — 5; Максим — Prolog — 2; Алина — Prolog — 5.

**7. Проверить конкретную оценку:**

```prolog
student_mark('Дима', 'Prolog', 5).
```

Ответ: `true`.

### Как объяснить правила

`student_grade/5` извлекает из `tabel/4` фамилию, имя, отчество, предмет и оценку. Структуры раскрываются внутри правила, поэтому в запросе достаточно перечислить нужные поля.

`student/3` сначала собирает уникальные ФИО через `setof/3`, затем `member/2` выдаёт их по одному. `Group^Subject^Result^` означает, что группа, предмет и результат не разделяют студентов на отдельные списки. Благодаря этому один студент не повторяется из-за нескольких предметов. Полное ФИО используется как идентификатор в этой учебной базе; люди с полностью одинаковыми ФИО потребовали бы дополнительного идентификатора.

```prolog
student_mark(Name, Subject, Grade) :-
    tabel(fio(_, Name, _), _, Subject, mark(Grade, _)).
```

Из `tabel` извлекаются имя, предмет и оценка. Фамилия, отчество, группа и дата не нужны этому запросу и заменены `_`. Каждый `_` независимо игнорирует свою позицию. В небольшой базе имена различаются; для тёзок нужно запрашивать полное ФИО через `tabel`.

```prolog
failed_student(Name, Subject, Grade) :-
    student_mark(Name, Subject, Grade),
    Grade < 3.
```

Сначала находим оценку, затем сравниваем её с тройкой. Запятая означает «и». В `high_mark` аналогично проверяется `Grade = 5` (совпадение с оценкой 5).

## Часть 2, вариант 4: расписание сессии

Основной файл **`part2_session.pl`** теперь использует **Visual Prolog 5.2**: в `domains` объявлен альтернативный тип `control = exam(...); credit(...)`, как в методичке. Инструкция и запросы для него — в [README_visual.md](README_visual.md). В SWISH этот файл не запускается. Ниже сохранено описание отдельного варианта `part2_session_swi.pl` для SWISH, без статической типизации.

### Точное задание из методички

**Часть 2. Улучшение структурированных баз знаний с помощью альтернативных доменов и списковых структур данных**

> Необходимо создать базу данных с использованием альтернативных доменных структур и встроенного механизма разработки списков.

**Вариант 4:**

> Разработать базу данных «расписание сессии» как список предметов, где зачёты и экзамены с представлены альтернативной структурой.

В последней цитате сохранена опечатка оригинала: «экзамены с представлены». По смыслу — «зачёты и экзамены представлены альтернативной структурой».

Источник: П. В. Новиков, «Логическое программирование на Visual Prolog 5.2», печатная страница 22 (страница 20 PDF).

### Реализация

Файл для SWISH: `part2_session_swi.pl`. Факт `session/2` хранит группу и список из пяти предметов. Элемент списка — `subject(Subject, Control)`. В `Control` записана одна из двух альтернатив:

```prolog
exam(Date, Time, Room, Teacher)
credit(Date, Time, Room, Teacher)
```

`exam` — экзамен; `credit` — зачёт. Данные внутри: `date(Day, Month, Year)`, `time(Hour, Minute)`, `room(Building, Number)`, `fio(Surname, Name, Patronymic)`.

### Как выбираются альтернативы

`session/2` и `session_subject/3` показывают исходные данные без проверки формы контроля. `exam_subject/6` выбирает только `exam/4`, а `credit_subject/6` — только `credit/4`, через сопоставление структур. Если записать `credit1(...)`, запись останется видна в общем поиске, но не будет найдена как экзамен или зачёт. Это не статическая проверка типов.

### Запросы для демонстрации

**1. Все данные расписания:**

```prolog
session(Group, Subjects).
```

Один ответ: группа ПИ-21 и полный список из пяти предметов со всеми вложенными полями. Это запрос на вывод всей базы по требованию методички.

**2. Все предметы и формы контроля по одному:**

```prolog
session_subject(Group, Subject, Control).
```

Пять ответов: Английский язык, История, Логика, Prolog, Математика — каждый с полной структурой контроля.

**3. Только экзамены:**

```prolog
exam_subject(Group, Subject, Date, Time, Room, Teacher).
```

| Предмет | Дата | Время | Аудитория |
|---|---|---|---|
| Логика | 15.01.2027 | 09:00 | А/301 |
| Prolog | 20.01.2027 | 10:00 | А/305 |
| Математика | 25.01.2027 | 09:00 | Б/210 |

Каждый ответ также содержит полное ФИО преподавателя.

**4. Только зачёты:**

```prolog
credit_subject(Group, Subject, Date, Time, Room, Teacher).
```

Английский язык — 10.01.2027, 10:00, А/201; История — 12.01.2027, 12:00, Б/105. Также выводятся ФИО преподавателей.

**5. Когда и у кого экзамен по Prolog:**

```prolog
exam_subject('ПИ-21', 'Prolog', Date, Time, Room, Teacher).
```

Ответ: `Date = date(20,1,2027)`, `Time = time(10,0)`, `Room = room('А',305)`, `Teacher = fio('Соколов','Павел','Андреевич')`.

**6. Экзамены в корпусе А:**

```prolog
exam_subject(_, Subject, _, _, room('А', Number), _).
```

Логика — 301; Prolog — 305.

**7. Количество предметов:**

```prolog
session('ПИ-21', Subjects), length(Subjects, Count).
```

Ответ: весь список `Subjects` и `Count = 5`.

### Как объяснить правила

```prolog
session_subject(Group, Subject, Control) :-
    session(Group, Subjects),
    member(subject(Subject, Control), Subjects).
```

Первое условие получает список расписания. `member(Element, List)` находит элемент в списке, а при переборе — следующий подходящий элемент. Здесь образец элемента — `subject(Subject, Control)`.

```prolog
exam_subject(Group, Subject, Date, Time, Room, Teacher) :-
    session_subject(Group, Subject, exam(Date, Time, Room, Teacher)).
```

Выбираются предметы с формой контроля `exam(...)`. Структура `credit(...)` не подходит, потому что её функтор другой. Зачёты находятся аналогично.

## Что могут спросить

- **Факт:** конкретное утверждение в базе, например `tabel(...)` с данными Димы.
- **Правило:** условие выполнения отношения; `:-` читается «если».
- **Предикат:** отношение, которое проверяется запросом. `tabel/4` имеет четыре аргумента, `session/2` — два.
- **Структура:** составной терм с несколькими полями, например `fio('Иванов','Дима','Сергеевич')`. `fio` — функтор; это не отдельный предикат базы. То же относится к `mark`, `date`, `time`, `room`, `subject`, `exam`, `credit` в аргументах фактов.
- **Альтернативные структуры:** разные варианты одного поля — здесь `exam(...)` или `credit(...)`.
- **Список:** последовательность элементов в квадратных скобках. `[]` — пустой список; `[Head|Tail]` — первый элемент и оставшийся список.
- **Унификация:** сопоставление запроса с фактом или правилом, при котором переменные связываются подходящими значениями.
- **Почему нет domains:** методичка написана для Visual Prolog 5.2. В SWI-Prolog структуры используются без этого раздела.

Вывод: вложенные термы объединяют связанные поля, списки хранят несколько предметов, а разные функторы различают экзамены и зачёты. Короткие правила извлекают нужные данные.

Источник: П. В. Новиков, «Логическое программирование на Visual Prolog 5.2», работа №2, печатные страницы 14–23. Выполнены заданные части 1/6 и 2/4.
